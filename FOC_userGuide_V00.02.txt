## 手册导读

**FOC（Field Oriented Control，磁场定向控制）** 是现代电动汽车驱动电机的标准控制方法。它的目标只有一个：**精确、快速地控制电机输出的扭矩**。

本手册将跟随一个扭矩指令在系统中"旅行"的完整路径，逐站解释每个环节在做什么、为什么这样做，以及工程代码里对应的是哪个函数。

## 第一章：FOC 是什么？为什么需要它？

### 1.1 电动汽车需要的是什么

驾驶员踩油门，期望的是立刻获得响应的扭矩。不管电机转速是快是慢，都要做到：
- **扭矩响应快**：踩下去就有，不能拖几百毫秒
- **扭矩精确**：指令10Nm就是10Nm，不能忽大忽小
- **高效率**：扭矩/电流比越高越好（电池续航）

### 1.2 为什么普通PWM控制不够

如果直接给电机施加固定幅值和频率的三相电压，会出现的问题：
- **低速时扭矩脉动大**：电流波形差，扭矩忽大忽小，车辆抖动
- **效率低**：大量电流产生的是热而不是扭矩
- **响应慢**：无法精确控制扭矩的大小

### 1.3 FOC 的核心思想：把交流电机"变成"直流电机

直流电机非常好控制：调节电流大小，扭矩就跟着变，简单直接。

FOC 的思想就是：**通过坐标变换，把三相交流电机在数学上等效为一台直流电机**，然后像控制直流电机一样控制它。

具体来说，FOC 将电机的电流分解成两个分量：

| 分量 | 名称 | 物理含义 | 类比 |
|------|------|----------|------|
| **Id**（d轴电流）| 励磁电流 | 控制磁通量大小 | 直流电机的励磁绕组电流 |
| **Iq**（q轴电流）| 扭矩电流 | 控制输出扭矩 | 直流电机的电枢电流 |

**关键结论**：
- 扭矩 ≈ Kt × Iq（扭矩系数 × q轴电流）
- **控制扭矩 = 控制 Iq**，就这么简单

## 第二章：坐标系——FOC 的数学地基

> **为什么要换坐标系**：三相交流量是不断旋转变化的，在原始坐标系里无法用 PI 控制器精确控制（PI 控制器只能控制直流量）。换到旋转坐标系后，交流变直流，就可以用 PI 了。

### 2.1 三个坐标系

```
自然坐标系（UVW）              静止坐标系（αβ）           旋转坐标系（dq）

       U轴                         β轴                      q轴
       ↑                           ↑                    θe  ↑
   Iu  │                       Iβ  │                        │  Iq
───────┼─────                  ────┼────                ────┼────
       │                           │  Iα                  Id│
V──────┘──────W                    └──── α轴               └──── d轴
                                                              θe = 转子电气角度
原始三相系统               120°相差消除后             与转子同步旋转
三路交流信号               两路交流信号               两路直流信号 ✓
```

### 2.2 Clarke 变换：UVW → αβ（消除第三相）

**背景**：三相电流满足 Iu + Iv + Iw = 0，只有两个独立量，所以可以降维到二维。

**数学公式**（等幅值变换）：
```
Iα = Iu
Iβ = (Iv - Iw) / √3
```

**物理含义**：把 120° 相差的三相坐标系，变换为垂直的两相坐标系（αβ轴），信息完全保留，只是换了种表达方式。

**代码位置**：`CoordinateTrans_if/`，函数 `IUVW2DQTrans()`

```c
// 工程实现
MotorCurrent.Ialpha = MotorCurrent.Iu;
MotorCurrent.Ibeta  = (MotorCurrent.Iv - MotorCurrent.Iw) * 0.57735F;
//                                                          ↑ 1/√3
```

### 2.3 Park 变换：αβ → dq（跟着转子转）

**背景**：αβ 坐标系是固定不动的，而电机转子在旋转。如果我们建立一个跟着转子一起旋转的坐标系（dq坐标系），那么在这个坐标系里，稳态时的电流就是**直流量**，可以用PI控制器了。

**数学公式**：
```
Id =  Iα × cos(θe) + Iβ × sin(θe)
Iq = -Iα × sin(θe) + Iβ × cos(θe)
```
其中 θe 是转子的**电气角度**（由旋变传感器测量）。

**物理含义**：
- d轴（direct axis）：与转子磁场方向**对齐**
- q轴（quadrature axis）：与转子磁场方向**垂直**（90°）
- 垂直方向的力产生扭矩，所以 **Iq ↔ 扭矩**

**代码位置**：`CoordinateTrans_if/`，函数 `IUVW2DQTrans()`

```c
float32 sinTheta = GFLIB_Sin(RDC_Read_Struct.AngleReal_s16) * INT2REAL; // sin(θe)
float32 cosTheta = GFLIB_Cos(RDC_Read_Struct.AngleReal_s16) * INT2REAL; // cos(θe)

MotorCurrent.Id =  MotorCurrent.Ialpha * cosTheta + MotorCurrent.Ibeta * sinTheta;
MotorCurrent.Iq = -MotorCurrent.Ialpha * sinTheta + MotorCurrent.Ibeta * cosTheta;
```

> **总结**：变换完成后，Id 和 Iq 在稳态下是直流量，我们就可以用 PI 控制器像控制直流电流一样控制它们了。

## 第三章：转子位置从哪来？

> **为什么需要转子位置**：Park 变换需要实时知道转子电气角度 θe，位置测量是 FOC 的"眼睛"。

### 3.1 旋变传感器（Resolver）

旋变是一种模拟式角度传感器，安装在电机轴上：
- 发射一路**激励信号**（正弦波）到旋变初级绕组
- 次级绕组根据转子位置，返回两路信号：**Sin信号** 和 **Cos信号**
- Sin/Cos 的幅值比值就包含了角度信息

```
激励：V_exc = A × sin(ωt)
返回：V_sin = k × sin(θ) × sin(ωt)
     V_cos = k × cos(θ) × sin(ωt)
因此：θ = atan2(V_sin, V_cos)
```

### 3.2 PLL 位置观测器（PositionObsr_if）

原始旋变信号是模拟量，必须经过数字解调才能得到角度。工程使用**锁相环（PLL）**：

```
┌──────────────────────────────────────────────────────┐
│                    PLL 锁相环                         │
│                                                       │
│  输入信号（旋变Sin/Cos） ─►  误差计算 ─► PI调节器     │
│                                  ▲           │       │
│                                  │           ▼       │
│                           估计位置PosEst ◄── 积分    │
│                                              │       │
│                                  ┌───────── Omega    │
│                                  │    （估计角速度）  │
│                                  └──────────────────►│
│                                    输出给速度计算     │
└──────────────────────────────────────────────────────┘
```

**误差计算**（叉积法）：
```
误差 e = sin(θ_est) × cos(θ_real) - cos(θ_est) × sin(θ_real)
       = sin(θ_est - θ_real)
       ≈ θ_est - θ_real  （小角度近似）
```
当估计角度等于实际角度时，误差为零，PLL 锁定。

**代码位置**：`PositionObsr_if/`，函数 `Pos_SWDemodulation()`

### 3.3 偏置角补偿（RDC_ReadOut_if）

旋变安装时不可能完美对齐，有机械偏差。解决方法：**出厂标定后将偏置角写入NVM**，每次上电读出来补偿。

```c
// RDC_ReadOut_App_ISR() 中
// 1. 加安装偏置（标定值，如44.2°，存在NVM里）
AngleReal_s16 = Angle_ReadOut + (int16_T)(ReslverOfst * 182.044F);

// 2. 加动态超前补偿（补偿Park变换的计算延迟）
//    电机在旋转，采样时到计算完成需要一定时间，期间转子又转了一些角度
AngleReal_s16 += (int16_T)(Spd_rpm_Flt * CompTm * 182.044F / 60.0F);
```

### 3.4 速度计算（Spd_Calcu_if）

PLL 输出的 Omega（角速度）经换算得到转速：

```
电频率 Fre_Hz = Omega → 换算（定点数转浮点）
转速 rpm = Fre_Hz × (60 / 极对数)
         = Fre_Hz × 20   （3对极时）
```

工程提供多个带宽的滤波转速，供不同用途使用：
- `Spd_rpm_Flt`：通用低通滤波（~250Hz）
- `Spd_rpm_spdlop`：速度环用（~25Hz，更平滑）
- `Spd_rpm_FltAbs`：绝对值版本（用于弱磁等）

## 第四章：扭矩从哪来？——从 VCU 到 FOC 的通信

### 4.1 多核架构：Core0 管理整车，Core2 管理电机

```
Core0（VCU应用层）                   Core2（FOC电机控制）
──────────────────                   ────────────────────
驾驶员踏板信号                              ↑
  → 扭矩仲裁（VCU_TrqArb）         IOC 核间通信
  → 最终扭矩需求（Nm）    ─────────────────►
  → 档位方向、限速...
  → 状态使能命令
```

**IOC（Inter-OS-Application Communicator）**：AUTOSAR 标准的核间通信机制，通过共享内存 + 同步原语实现，Core0 把扭矩指令"写"进共享内存，Core2 周期性"读"出来。

> **为什么两个核？**：电机控制（Core2）需要25µs高速中断，而整车逻辑（Core0）只需要1ms~10ms更新。分开放在不同核上，互不干扰，各自专注。

### 4.2 Core2 收到的信号

通过 IOC，Core2 从 Core0 收到的关键信号（在 `IOC_Comm_McuM_Rx_Core2.c` 中读取）：

| 信号名 | 含义 |
|--------|------|
| `In_FLT_TorFromTorMode` | 扭矩模式下的扭矩指令（Nm）|
| `In_FLT_TorFromSpdMode` | 速度模式下的扭矩指令（Nm）|
| `In_UINT8_RunMode` | 运行模式（1=速度模式，2=扭矩模式）|
| `VCU_Msg.VCU_VehicleDirect` | 车辆方向（前进/后退）|

## 第五章：状态机——电机能不能转？

**代码位置**：`AppModel/StateMachine/`，函数 `StateMachine_step()`（每500µs调用）

在扭矩指令正式进入控制器之前，**状态机**先做决策：电机现在应该处于什么状态？

### 5.1 电机工作状态

```
          ┌─────────────────────────────────────────┐
          │                                         │
   上电 ──► IDLE（空闲）──► TORQUE_STATE（扭矩模式）│
          │      │                    ↑↓            │
          │      └──► SPD_STATE（速度模式）         │
          │                           ↕             │
          │      ALIGN_STATE（角度对齐）             │
          │      CALIB_STATE（标定）                 │
          │      DISCHARGE_STATE（主动放电）         │
          │      SHUTDOWN_STATE（关机）              │
          └─────────────────────────────────────────┘
```

| 状态 | 含义 | 电流指令来源 |
|------|------|-------------|
| `IDLE` | 空闲，不输出扭矩 | Id=0, Iq=0 |
| `TORQUE_STATE` | **正常驾驶（最常用）** | IDQ查表 → 正常驱动 |
| `SPD_STATE` | 速度闭环模式 | 速度PI → IDQ查表 |
| `ALIGN_STATE` | 启动前角度对齐 | 固定Id注入 |
| `CALIB_STATE` | 旋变偏置角标定 | 标定专用电流 |
| `DISCHARGE_STATE` | 高压放电 | 放电专用电流 |
| `SHUTDOWN_STATE` | 关机过渡 | Id=0, Iq=0 |

**代码**：
```c
// StateMachine.c
void StateMachine_step(void)
{
    StmInp();  // 读取所有输入条件（VCU使能、故障、温度等）
    Stm();     // 执行状态转换逻辑
    StateMachineStruct.Out_U16_State = Out_U16_State;  // 输出当前状态
}
```

## 第六章：扭矩仲裁——扭矩指令如何被"审核"

**代码位置**：`AppModel/TorCMD_Arbit/`，函数 `TorCMD_Arbitrate_App_500us()`（每500µs调用）

扭矩仲裁解决一个问题：**VCU 想要的扭矩，是否安全可行？**

### 6.1 仲裁逻辑

```
来自VCU的扭矩需求（Nm）
        │
        ├── 运行模式选择（TorFromRunMode）
        │   ├── 速度模式（RunMode=1）→ 用速度环输出的扭矩
        │   └── 扭矩模式（RunMode=2）→ 直接用VCU扭矩
        │
        ▼
        TorFromRunMode输出：Out_FLT_Tor2DQTab（初始值）
        │
        ├── 故障保护限制（In_FLT_TorFromDecPow）
        │   功率降额保护：过温/过流时缩小允许的最大扭矩
        │
        ├── 外充扭矩限制（In_FLT_TorFromExChar）
        │   充电工况时的扭矩上限
        │
        ├── OC检测后的限制（OC_torque_limit_level_1）
        │   发生过一次硬件过流后，最大正向扭矩限到 TORARBI_LIMIT_FOR
        │
        └── 倒车方向限制（VCU_VehicleDirect=1）
            倒车时限制最大扭矩到 TORARBI_LIMIT_BACK
        │
        ▼
    MinTorCmp：取所有限值中的最小值
        │
        ▼
    最终仲裁后的扭矩：Out_FLT_Tor2DQTab（Nm）
```

### 6.2 代码解读

```c
// TorCMD_Arbitrate.c

// Step1：根据运行模式选择扭矩来源
void TorFromRunMode(void)
{
    switch (TorCMD_Arbi.In_UINT8_RunMode) {
        case 1:  // 速度模式：用速度PI输出的扭矩
            TorCMD_Arbi.Out_FLT_Tor2DQTab = TorCMD_Arbi.In_FLT_TorFromSpdMode;
            break;
        case 2:  // 扭矩模式（正常驾驶）：直接用VCU扭矩
            TorCMD_Arbi.Out_FLT_Tor2DQTab = TorCMD_Arbi.In_FLT_TorFromTorMode;
            break;
        default: // 其他状态：零扭矩
            TorCMD_Arbi.Out_FLT_Tor2DQTab = 0.0F;
    }
}

// Step2：与保护限值比较，取最小值
void MinTorCmp(void)
{
    // 取两个限制中更严格的（更小的绝对值）
    TorCMD_Arbi.In_FLT_TorLimit = fminf(
        fabsf(TorCMD_Arbi.In_FLT_TorFromDecPow),   // 功率降额限制
        fabsf(TorCMD_Arbi.In_FLT_TorFromExChar));   // 外充限制

    // 将扭矩钳位在 ±TorLimit 范围内
    if (TorCMD_Arbi.Out_FLT_Tor2DQTab > TorCMD_Arbi.In_FLT_TorLimit)
        TorCMD_Arbi.Out_FLT_Tor2DQTab = TorCMD_Arbi.In_FLT_TorLimit;
    else if (TorCMD_Arbi.Out_FLT_Tor2DQTab < -TorCMD_Arbi.In_FLT_TorLimit)
        TorCMD_Arbi.Out_FLT_Tor2DQTab = -TorCMD_Arbi.In_FLT_TorLimit;
}
```

## 第七章：MTPA 查表——扭矩如何变成电流指令

**代码位置**：`AppModel/APP_Call_Interface/IDQ_LookUpTable_App.c`，调用 `IDQ_LookUpTable_step()`

这是 FOC 中最核心的环节之一，回答的问题是：**要输出 X Nm 的扭矩，Id 应该给多少？Iq 应该给多少？**

### 7.1 为什么不直接用公式算 Id/Iq？

最简单的做法：令 Id = 0，Iq = 扭矩 / 扭矩系数 Kt。

这在低速时有效，但并非最优。原因：
- 永磁同步电机除了磁阻扭矩（靠 Iq），还有**磁阻扭矩**（靠 Id-Iq 组合）
- 对于凸极电机（Ld ≠ Lq），适当注入负 Id 可以在同等电流下获得更大扭矩

### 7.2 MTPA（Maximum Torque Per Ampere，每安培最大扭矩）

MTPA 是在给定电流幅值约束下，找到使扭矩最大的 Id/Iq 组合点。这个组合点是通过**仿真或实测**预先计算好，以**查找表**的形式存储在 Flash 中。

```
                  Iq
                  ↑
              ↗   │    MTPA曲线（最优工作点轨迹）
          ↗       │
      ↗           │         • 沿MTPA曲线：同样的扭矩，电流最小
  ↗               │         • 这意味着：铜损最小，效率最高
──────────────────┼──────────── Id（负值在左）
       Id < 0     │
       (基速区注入少量负Id提升效率)
```

### 7.3 查表逻辑

```c
// IDQ_LookUpTable_App.c

void IDQ_LookUpTable_App_500us(void)
{
    // 确认处于可运行状态
    if (StateMachineStruct.Out_U16_State == TORQUE_STATE || ...)
    {
        // 查表输入1：仲裁后的扭矩指令
        PointSearch.In_FLT_Trq = TorCMD_Arbi.Out_FLT_Tor2DQTab;

        // 查表输入2：当前转速（rpm）
        PointSearch.In_FLT_Spd = SpdCalcu_Struct.Spd_rpm_FltAbs;

        // 查表输入3：当前母线电压（V）
        PointSearch.In_FLT_Vdc = Vbus.Filt_OutValue;

        // 执行查表（2D/3D插值）
        IDQ_LookUpTable_step();
        // 查表结果：
        // PointSearch.Out_FLT_Idref → d轴电流参考
        // PointSearch.Out_FLT_Iqref → q轴电流参考

        // 将结果传递给电流仲裁
        CurtCMD_Arbi.In_FLT_IdFromDQTab = PointSearch.Out_FLT_Idref;
        CurtCMD_Arbi.In_FLT_IqFromDQTab = PointSearch.Out_FLT_Iqref;
    }
}
```

**查表的本质**：是一张 Excel 表格，行是扭矩，列是转速（有时还加母线电压），每个格子填写该工况下最优的 Id 和 Iq。运行时通过插值查出中间值。

## 第八章：弱磁控制——高速时如何维持扭矩

**代码位置**：`FOC/FluxWeaken_if/`，函数 `FWCtrlAppNew_500us()`（每500µs调用）

### 8.1 问题：高速时的电压瓶颈

电机高速旋转时，反电动势（EMF）会升高：
```
EMF ≈ Ke × ω（转速越高，反电动势越大）
```

逆变器能输出的最大相电压是有限的（约 Udc/√3），当 EMF 接近这个上限时：
- 再增大扭矩（增大 Iq）会导致电压超限
- 逆变器失去控制能力，电流失控

### 8.2 解决方案：注入负 Id 来减弱磁场

反电动势来自永磁体磁场。注入负 d 轴电流（Id < 0），可以用定子电流产生的磁场**抵消**部分永磁体磁场：
```
实际磁通 = 永磁体磁通 - |Id| × Ld（d轴电感）
EMF ∝ 实际磁通 × ω
```
减弱磁场 → EMF 降低 → 电压余量恢复 → 可以维持对 Iq 的控制

**代价**：Id < 0 不产生扭矩，但要消耗电流，所以效率有所下降。

### 8.3 弱磁区与基速区的区别

```
扭矩
↑
│     基速区                弱磁区
│ (Id≈0或MTPA)        (Id<0，逐渐增大)
│──────────────────┐
│                  │╲
│                  │  ╲  恒功率曲线
│                  │    ╲
│                  │      ╲
└──────────────────┴────────────────→ 转速
                 基速(Base Speed)
```

### 8.4 代码逻辑

```c
// FluxWeaken_if 中，简化表示

void FWCtrlAppNew_500us(void)
{
    // 计算逆变器能提供的最大电压幅值
    float Uavail = MaxVoltCoeff * Udc;   // MaxVoltCoeff≈0.585 = 1/√3

    // 当前实际输出电压幅值
    float Uout = CurCtrl.Us_MagApply;   // 来自PI输出

    // 电压余量（正值表示还有余量，负值表示已经超限）
    float VoltError = Uavail - Uout;

    if (Spd_rpm_FltAbs > Spd_Turn) {    // 超过基速，进入弱磁
        // 积分控制：电压超限时，积分器积分出负的Id
        Integ_L1 += Ki_FW * VoltError;
        // 限制：Id只能为负（否则反而增强磁场）
        IdSetFnl = CLAMP(IdLUT + Integ_L1, Id_Min, 0.0F);
    } else {                            // 基速以下，用MTPA结果
        IdSetFnl = IdLUT;               // IdLUT来自IDQ查表
        Integ_L1 = 0.0F;               // 清零积分，准备再次进入弱磁
    }
}
```

## 第九章：电流仲裁——最终送给 PI 的是哪路电流？

**代码位置**：`AppModel/CurtCMD_Arbit/`，函数 `CurtCMD_Arbit_App_500us()`（每500µs调用）

到这一步，系统可能有多个电流来源（正常驱动、加热、标定、放电），需要根据当前状态选择一路送给 PI 控制器。

```c
void CurrentCMD_Arbitrate_step(void)
{
    switch (CurtCMD_Arbi.In_UINT8_ModeReq) {

        case 1: // RUN 模式（正常驾驶）
            // 使用IDQ查表 + 弱磁叠加后的结果

            Out_FLT_Iq2foc = In_FLT_IqFromDQTab;    // MTPA后的Iq

        case 2: // CALIB 模式（旋变偏置角标定）
            Out_FLT_Id2foc = In_FLT_IdFromCAL;
            Out_FLT_Iq2foc = In_FLT_IqFromCAL;

        case 3: // BLOCK_HEAT 模式（堵转加热）
            // 注入纯d轴电流，产生热量但不产生扭矩
            Out_FLT_Id2foc = In_FLT_IdFromSysHeat;  // 负d轴大电流

    }
```

## 第十章：电流 PI 控制——控制回路的心脏

**代码位置**：`FOC/Current_Control_if/`，函数 `CurntCtrl_ISR()`（每25µs调用）

### 10.1 PI 控制器是什么

PI 控制器（比例-积分控制器）是自动控制的基础模块，目标是让被控量精确跟随参考值。

```
误差 e(t) = 参考值 - 实际值
                │
        ┌───────┴───────┐
        │               │
    比例项 Kp×e      积分项 Ki×∫e dt
    （快速响应）      （消除稳态误差）
        │               │
        └───────┬───────┘
                │
            输出 u(t)
```

- **Kp（比例增益）**：误差越大，输出越大；使系统快速响应，但过大会振荡
- **Ki（积分增益）**：对误差积分，消除静差；但过大会超调

### 10.2 为什么是两个独立的 PI（d轴一个，q轴一个）

d 轴和 q 轴虽然理论上解耦，但实际电机中存在耦合项（ω×Lq×Iq 和 ω×Ld×Id 的交叉项）。两个独立 PI 分别控制 Id 和 Iq，简单有效。

### 10.3 代码逻辑

```c
void CurntCtrl_ISR(void)
{
    // ====== 读入参考值（来自电流仲裁）======
    Id_Ref = CurtCMD_Arbi.Out_FLT_Id2foc;
    Iq_Ref = CurtCMD_Arbi.Out_FLT_Iq2foc;

    // ====== 读入反馈值（来自坐标变换）======
    Id_Fb = MotorCurrent.IdFbk_Flt;    // 低通滤波后的d轴反馈电流
    Iq_Fb = MotorCurrent.IqFbk_Flt;    // 低通滤波后的q轴反馈电流

    // ====== 计算误差 ======
    float err_d = Id_Ref - Id_Fb;      // d轴误差（A）
    float err_q = Iq_Ref - Iq_Fb;      // q轴误差（A）

    // ====== PI 计算（输出电压，单位V）======
    float Ud_PI = Kp_d * err_d + Integ_d;   // d轴电压
    float Uq_PI = Kp_q * err_q + Integ_q;   // q轴电压

    // ====== 电压矢量限幅（防止超出逆变器能力）======
    float Us_Max = MaxVoltCoeff * Udc;      // 最大允许电压（≈ Udc/√3）
    float Us_Mag = sqrtf(Ud_PI*Ud_PI + Uq_PI*Uq_PI);  // 实际电压幅值

    if (Us_Mag > Us_Max) {
        float scale = Us_Max / Us_Mag;
        Ud_out = Ud_PI * scale;              // 等比例缩小，保持方向不变
        Uq_out = Uq_PI * scale;
        SatFlag = 1;                         // 标记：进入饱和
    } else {
        Ud_out = Ud_PI;
        Uq_out = Uq_PI;
        SatFlag = 0;
    }

    // ====== 积分更新（含抗饱和）======
    // 正常时：积分累积误差
    // 饱和时：Anti-Windup 机制抑制积分继续增大
    if (!SatFlag) {
        Integ_d += Ki_d * err_d;
        Integ_q += Ki_q * err_q;
    } else {
        // Back-Calculation 抗饱和：减去超出部分，防止积分过大
        Integ_d += Ki_d * err_d + KawCoeff * (Ud_out - Ud_PI);
        Integ_q += Ki_q * err_q + KawCoeff * (Uq_out - Uq_PI);
    }
}
```

### 10.4 参数含义与动态缩放

| 参数 | 典型值（10kHz）| 作用 |
|------|----------------|------|
| `Kp_d` | 0.38 | d轴比例增益（太大→震荡，太小→响应慢）|
| `Ki_d` | 0.0036 | d轴积分增益（太大→超调，太小→消差慢）|
| `Kp_q` | 0.56 | q轴比例增益（q轴响应更快，增益更大）|
| `KawCoeff` | 0.75 | 抗饱和强度 |

**增益随开关频率动态缩放**：开关频率翻倍时，每个控制周期更短，等效积分时间变短，所以增益也等比例增大，保持控制带宽一致。

## 第十一章：SVPWM——把电压变成 PWM 占空比

**代码位置**：`FOC/Volt_Modulate_if/`，函数 `SVM()`（每25µs调用）

### 11.1 问题：如何实现任意电压矢量？

PI 控制器输出的是 Ud、Uq（dq 坐标系下的电压），我们需要把它转换成三个 IGBT 桥臂的开关指令（占空比）。

### 11.2 Park 逆变换（dq → αβ）

先把 dq 坐标系的电压变回静止坐标系：
```
Uα = Ud × cos(θe) - Uq × sin(θe)
Uβ = Ud × sin(θe) + Uq × cos(θe)
```
这样得到静止坐标系下的电压矢量 (Uα, Uβ)。

### 11.3 SVPWM 的核心思想

三相逆变器的每个桥臂只有开和关两种状态（1/0），三个桥臂组合出 8 种电压矢量：

```
      V3(010) = 逆变器第2桥臂上管导通，其余下管
       ╱   ╲
V4(011)       V2(110)
  │    V0(000) V7(111)  │
  │    (两个零矢量)     │
V5(001)       V1(100)
       ╲   ╱
      V6(101)
```

目标：用这 8 个基本矢量的**时间加权平均**，合成任意所需的电压矢量 (Uα, Uβ)。

**7段式SVPWM时序**（以扇区1为例，矢量 V1+V2）：

```
一个PWM周期内的开关顺序（中心对齐）：
时间轴：  T0/4  T1/2  T2/2  T0/2  T2/2  T1/2  T0/4
U相：  ──────────────────────────────────────────────
V相：          ────────────────────────────
W相：                  ──────────
```

- T1：第一个有效矢量的作用时间
- T2：第二个有效矢量的作用时间
- T0：零矢量时间（上管全通 V7 或 下管全通 V0）

**三相占空比**由这三个时间决定。

### 11.4 代码逻辑

```c
void SVM(void)
{
    // Step1：Park逆变换（dq → αβ）
    Ualpha = Ud_out * cosTheta - Uq_out * sinTheta;
    Ubeta  = Ud_out * sinTheta + Uq_out * cosTheta;

    // Step2：计算电压矢量的幅值和相角
    //   幅值 = |Us| = √(Uα² + Uβ²)
    //   相角 = atan2(Uβ, Uα)

    // Step3：计算调制指数（幅值 / 最大线性调制电压）
    MI = |Us| / (Udc / √3)

    // Step4：根据相角确定扇区（0°~60°为扇区1，60°~120°为扇区2...）
    SecNum = (int)(PhaseUs / (π/3))   // 0~5

    // Step5：计算矢量作用时间
    T1 = MI × sin(60° - 扇区内余角) / sin(60°)
    T2 = MI × sin(扇区内余角) / sin(60°)
    T0 = 1.0 - T1 - T2

    // Step6：根据扇区查表，确定三相占空比
    DutyU/V/W = 按扇区的组合关系
}
```

### 11.5 过调制（OVM）

当 MI > 1（需要的电压超过了线性调制的上限），SVPWM 会进入过调制区，牺牲低次谐波控制来换取更高的基波电压，工程支持两个过调制区：
- OVMzoom1：部分六拍波，谐波增加但扭矩还能控制
- OVMzoom2：完整六拍方波，最大电压利用率但谐波最大

## 第十二章：死区补偿——小细节，大影响

**代码位置**：`FOC/DeadBandComp_if/`，函数 `DBComp_3PhsComp()`

### 12.1 死区是什么

每个桥臂有上管和下管，切换时必须有一段两者都关断的时间（死区，约2µs），防止上下管直通短路炸机。

```
上管：  ━━━━━━━┐              ┌━━━━━━━
下管：         └──────────────┘
               ← 死区时间 →
```

### 12.2 死区导致的电压误差

死区期间，实际相电压由电流方向决定（续流二极管导通），而不是由PWM指令决定：
- 相电流 > 0：实际电压偏低（少了死区时间对应的正电压）
- 相电流 < 0：实际电压偏高（多了死区时间对应的负电压）

这个误差在低速大电流时最明显，会导致电流谐波增大，扭矩脉动变大。

### 12.3 补偿方法

在SVPWM输出的占空比上叠加一个补偿量，方向与相电流符号相关：

```c
// 补偿量幅值 = 死区时间 / PWM周期 = 400 / 50000 = 0.008（20kHz时）
float CompValue = DeadBandTime / PwmPeriod;

// 根据各相电流方向确定补偿方向
// 正电流：补偿为正（增大占空比）
// 负电流：补偿为负（减小占空比）
CompU = -CompValue * sign(Iu);  // sign函数有迟滞，防止过零抖动
CompV = -CompValue * sign(Iv);
CompW = -CompValue * sign(Iw);
```

## 第十三章：PWM 输出——把数字写进硬件

**代码位置**：`FOC/PWM_OutputSwitch_if/`，函数 `PWM_OutputSwitch_App_ISR()`（每25µs调用）

这是控制回路的最后一步，把浮点占空比（0~1）转换为硬件定时器的计数值：

```c
void PWM_OutputSwitch_App_ISR(void)
{
    // SVPWM输出（0~1浮点）+ 死区补偿
    duty_U = VoltModu.UaM + DBComp.CompU;
    duty_V = VoltModu.UbM + DBComp.CompV;
    duty_W = VoltModu.UcM + DBComp.CompW;

    // 限幅（防止超出有效范围）
    duty_U = CLAMP(duty_U, MinDuty, MaxDuty);
    // ...

    // 转换为定时器 ticks（中心对齐PWM，比较值 = 半周期 × 占空比）
    // 20kHz时：Prd_Ticks = 50000（GTM时钟100MHz / 20kHz / 2）
    Duty_U_Real = (uint32)(Prd_Ticks * duty_U);
    // ...

    // 写入 GTM ATOM 硬件寄存器
    PWM_duty_set(PHASE_U, Duty_U_Real);
    PWM_duty_set(PHASE_V, Duty_V_Real);
    PWM_duty_set(PHASE_W, Duty_W_Real);
}
```

**硬件：GTM ATOM**（Generic Timer Module - Atom Timer Output Module）是 TC377 专用的高精度 PWM 发生器，三路 ATOM 通道同步输出三相 PWM，并在载波谷值时自动触发 ADC 采样。

## 第十四章：ADC 采样——测量反馈电流

**代码位置**：`FOC/AdcInfo_if/`，函数 `ADC_Read_Isr()`（每25µs调用，由PWM触发）

### 14.1 采样时机的选择

ADC 采样必须在**电流最稳定的时刻**进行——PWM 载波的**谷值处**（所有相都在中间状态，开关动作已完成，电流纹波最小）。这由 GTM 硬件自动同步触发。

```
PWM波形（中心对齐）：
        ┌───┐     ┌───┐
上管：  │   │     │   │
────────┘   └─────┘   └────
                            ADC触发（谷值）
                   ↓
电流波形（纹波）：
        ～～～↓～～～↓～～
               采样点
```

### 14.2 电流零点校准

电流传感器有零点漂移，需要在电机静止时校准：

```c
void CurrentSensorOffsetCalc05ms(void)
{
    // 在电机不通电时，理论上三相电流为0
    // 实际ADC读数≠0，这个偏差就是零点误差
    // 连续采128个样本取平均
    accumulator += ADC_raw;
    sampleCount++;
    if (sampleCount >= 128) {
        Offset = accumulator / 128;   // 等价于右移7位
        accumulator = 0;
        sampleCount = 0;
    }
}
```

### 14.3 直流母线电压滤波

Udc 用于 SVPWM 归一化和弱磁计算，需要稳定值：

```c
// 一阶低通滤波（α = 0.001，截止频率约3Hz）
// 滤除高频纹波，保留直流分量
Udc_Filt = α × Udc_Raw + (1 - α) × Udc_Filt_Last;
```

## 第十五章：完整闭环——把所有环节串起来

### 15.1 FOC 闭环的本质

```
参考         ┌─────────────┐    实际
Id_Ref ─►(-)─► d轴PI控制器 ├──► Ud_out ──►┐
         ▲   └─────────────┘              │
         │                                │  SVPWM → PWM → 逆变器 → 电机
         │   ┌─────────────┐              │
Iq_Ref ─►(-)─► q轴PI控制器 ├──► Uq_out ──┤
         ▲   └─────────────┘              │
         │                                │
         └──── Park变换 ◄── Clarke变换 ◄── ADC采样（Iu,Iv,Iw）
         └──── 需要转子角θ（来自旋变+PLL）
```

这是一个**双闭环控制系统**：
- **内环（电流环）**：25µs 更新，快速精确控制 Id/Iq
- **外环（转速环或扭矩环）**：500µs 更新，从系统级给出 Id/Iq 参考值

### 15.2 各模块执行频率与职责

| 执行频率 | 模块 | 职责 |
|----------|------|------|
| **25µs（ISR，最高优先）** | ADC_Read_Isr | 采样三相电流和Udc |
| | RDC_ReadOut_App_ISR | 旋变角度解算 |

### 15.3 一次完整的扭矩响应（时序追踪）

**场景**：驾驶员踩油门，VCU 计算出需要 200Nm 扭矩，发送给 Core2。

```
T=0ms   VCU 通过 IOC 写入扭矩指令 TorFromTorMode = 200Nm

T=0.5ms  【500µs任务】
         1. StateMachine_step() → 确认处于 TORQUE_STATE
         2. TorCMD_Arbitrate()  → 200Nm 通过限制检查 → Out_FLT_Tor2DQTab = 200Nm
         3. IDQ_LookUpTable()   → 查表：200Nm@2000rpm → Id=-20A, Iq=300A
         4. FWCtrlApp()         → 2000rpm < 基速，不弱磁 → Id=-20A 不变
         5. CurrentCMD_Arbit()  → TORQUE_STATE → Id2foc=-20A, Iq2foc=300A

T=0.525ms 【下一个25µs ISR】
         6. ADC_Read_Isr()       → 采样：Iu=280A, Iv=-150A, Iw=-130A（旧值，尚未响应）
         7. RDC+PLL()            → 转子角θ=45°，转速=2000rpm
         8. IUVW2DQTrans()       → Clarke: Iα=280, Iβ=-16.2
                                  → Park(θ=45°): Id=-17A, Iq=278A
         9. CurntCtrl_ISR()
             err_d = -20 - (-17) = -3A   → Ud_out = Kp_d×(-3) + Integ_d
             err_q = 300 - 278  = +22A  → Uq_out = Kp_q×(+22) + Integ_q
             → Ud_out=-5V, Uq_out=35V（举例）
        10. SVM()                → Ud=-5V, Uq=35V + 转子角 → DutyU=0.62, DutyV=0.35, DutyW=0.53
        11. DBComp()             → 叠加死区补偿量
        12. PWM_Output()         → 写入GTM：31000 ticks, 17500 ticks, 26500 ticks

T=0.55ms  IGBT 按新占空比切换 → 电机施加新的三相电压 → 电流开始变化

... 经过多个25µs周期，电流逐渐收敛到 Id=-20A, Iq=300A ...

T≈5ms    扭矩稳定在200Nm（电流环带宽约1kHz，约1ms达到稳定）
```

## 第十六章：特殊工况下的 FOC

### 16.1 主动加热（System_Heating）

**场景**：冬天电池温度低，需要加热。

**方法**：令 Iq = 0，注入大负 Id（如 -300A）。
- Iq = 0 → 不产生扭矩 → 车辆不动
- Id ≠ 0 → 在电机绕组上产生 I²R 热量
- 同时 RDC_ReadOut 中的 `EMH_AngleLockFlg` 会将角度锁定在12个扇区位置，确保电流分布均匀

| 加热级别 | 注入 Id | 功率（估算）|
|----------|---------|------------|
| Level 5 | -330 A | 最大加热 |
| Level 4 | -320 A | |
| Level 3 | -295 A | |
| Level 2 | -260 A | |
| Level 1 | -210 A | |

### 16.2 谐波抑制（Harmonics_Controller）

**场景**：中高速时电机出现啸叫（NVH 问题）。

**原因**：永磁体磁场含有空间谐波（5次、7次），在 dq 坐标系中表现为 6倍频脉动（6×基频的扭矩波动）。

**方法**：向 d/q 轴电流参考中**叠加特定幅值和相位的谐波补偿分量**，主动抵消谐波扭矩：

```c
// ISR 中叠加到电流参考
float theta_6th = 6.0F × AngleReal_s16 × INT2RAD;  // 6倍频角度
dAxisRpl = Mag × cos(theta_6th + Phase);
qAxisRpl = Mag × sin(theta_6th + Phase);
// Mag 和 Phase 从2D查找表查取（转速×扭矩索引）
```

### 16.3 主动短路（ASC，Active Short Circuit）

**场景**：逆变器发生故障（如驱动芯片报错），需要快速安全停机。

**方法**：不是直接关断所有开关管（这会让电机反电动势无处消耗，产生过压），而是：
- 将三相**下管全部导通**（或上管全部导通）
- 电机短路，反电动势驱动短路电流，能量在绕组电阻中消耗
- 电流快速衰减至零，安全停机

## 第十七章：FOC 初学者常见问题

### Q1: d 轴和 q 轴到底是什么意思？我总是搞混。

**类比**：想象你在看一个转动的陀螺。
- **静止坐标（αβ）**：你站在地上看，陀螺的针在360°旋转
- **旋转坐标（dq）**：你跟着陀螺一起转，这样看陀螺的针就静止了

d 轴始终指向转子磁场方向（就像陀螺的轴线），q 轴与 d 轴垂直。

在 dq 坐标系里：
- d 轴电流（Id）= 与磁场**同方向**的电流 = 调节磁场强度（不产生扭矩）
- q 轴电流（Iq）= 与磁场**垂直**的电流 = 产生扭矩（F = BIL，力与磁场垂直）

### Q2: 为什么基速区 Id = 0，而弱磁区 Id < 0？

- **基速区**：反电动势小于逆变器极限，有足够的电压余量控制 Iq，Id=0 最高效
- **弱磁区**：反电动势接近上限，如果 Id=0，电压全被反电动势占用，没法再给 Iq 施加有效电压。注入负 Id，抵消部分永磁体磁场 → 反电动势降低 → 腾出电压余量 → 可以继续控制 Iq → 维持扭矩输出

### Q3: SVPWM 比普通正弦 PWM 好在哪？

SVPWM 通过插入零矢量（V0/V7），让三相输出的平均值叠加了一个三次谐波，**相电压中有三次谐波，但线电压中三次谐波相互抵消**。效果：相同直流母线电压下，SVPWM 能输出的基波电压比正弦 PWM 高约 15%（1/√3 vs 0.5）。

### Q4: 抗饱和（Anti-Windup）为什么重要？

没有抗饱和时：如果PI输出超过限幅（比如弱磁限制），**积分项还在持续累积**，会积到很大的值。一旦条件改变允许输出了，积分项放出来会造成极大的冲击（超调），可能触发过流保护甚至损坏硬件。

抗饱和确保积分项不会在饱和时无限增大，是电机控制的安全必需品。

### Q5: 为什么 Kp 要随开关频率缩放？

PI 积分项的有效增益取决于调用频率：
- 20kHz 时每次积分 Ki × e，积累速度是 10kHz 时的2倍
- 为了保持同样的带宽，20kHz 时 Ki 应该减半（或者说10kHz增益按比例缩小）
- 工程的做法反过来，以20kHz为基准，10kHz时把增益减半

### Q6: 这个工程有速度环吗？

有，在 `AppModel/SpdLoop/` 目录。速度环是**外环**，以转速为目标，输出扭矩指令，再通过MTPA查表转换为电流指令，送给内环（电流PI）。

正常驾驶通常用**扭矩模式**（直接控制扭矩），速度模式用于特定工况（如怠速控制）。
